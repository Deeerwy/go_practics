## Реализация HTTPS (TLS-сертификаты). Защита от SQL-инъекций. Бурылин Дмитрий ПИМО-01-25
Данный проект создан в рамках практического занятия по изучению безопасности backend-приложений. Он демонстрирует базовые инженерные практики: настройку защищенного соединения (HTTPS/TLS) и безопасную работу с базой данных PostgreSQL для предотвращения SQL-инъекций.

## Структура проекта

- `cmd/server/` — точка входа в приложение (запуск HTTPS-сервера).
- `certs/` — директория для хранения локальных TLS-сертификата и приватного ключа.
- `internal/config/` — конфигурация приложения (DSN, порты, пути).
- `internal/httpapi/` — HTTP-обработчики маршрутов.
- `internal/student/` — бизнес-модели и слой взаимодействия с базой данных (Repository).
- `sql/` — SQL-скрипты для инициализации структуры и тестовых данных.

## Требования

Для запуска проекта локально потребуется:
- Установленный **Go** (версия 1.18+).
- Установленный **PostgreSQL**.
- Утилита **OpenSSL** (для генерации TLS-сертификатов).

### 1. Подготовка базы данных

Запустили PostgreSQL, создли базу данных (например, `study_security`) + инициализация таблиц:

```bash
psql -U postgres -d study_security -f sql/init.sql
```

### 2. Генерация TLS-сертификата

```
openssl req -x509 -newkey rsa:2048 -nodes -keyout certs/server.key -out certs/server.crt -days 365 -subj "/CN=localhost"
```

### 2. Запуск приложения

```
go mod tidy
go run ./cmd/server
```

### Ответы на контрольные вопросы

#### Чем HTTP отличается от HTTPS?
HTTP передаёт данные в открытом виде, без шифрования. HTTPS использует протокол TLS для криптографической защиты канала передачи данных, что обеспечивает их конфиденциальность и целостность при передаче по сети.

#### Какую роль выполняет TLS в защищённом соединении?
TLS (Transport Layer Security) шифрует данные между клиентом и сервером, удостоверяет подлинность сервера с помощью сертификатов и защищает передаваемую информацию от изменений в процессе транзита путем проверки целостности.

#### Что такое TLS-сертификат?
Это цифровой криптографический документ, который содержит публичный ключ сервера и подтверждает его идентичность. Он используется клиентом (например, браузером) для проверки того, что сервер — именно тот, за кого себя выдаёт.

#### Что делает tls.LoadX509KeyPair?
В стандартной библиотеке Go эта функция читает два файла в формате PEM (сертификат и приватный ключ), парсит их и возвращает объект структуры tls.Certificate, который затем используется в конфигурации TLS-сервера.

#### Почему self-signed certificate подходит для локальной учебной среды, но не для публичного production-сервиса?
Самоподписанный (self-signed) сертификат не заверен глобальным доверенным Удостоверяющим Центром (CA). В браузере он вызывает предупреждение о небезопасном соединении. В учебных целях этого достаточно для работы по HTTPS, но в production-среде подобное предупреждение отпугнет реальных пользователей.

#### Что такое SQL-инъекция?
Это уязвимость безопасности, которая возникает, когда недобросовестный пользовательский ввод изменяет ожидаемую структуру SQL-запроса, позволяя злоумышленнику выполнить несанкционированные команды в базе данных.

#### Почему конкатенация строки SQL с пользовательским вводом опасна?
Потому что СУБД не может отличить, где заканчивается ваш SQL-код и где начинаются данные пользователя. Если в данных есть спецсимволы (например, кавычки или слова вроде OR), они будут интерпретированы как часть исполняемого запроса (например, ... WHERE id = 1 OR 1=1).

#### Что такое parameterized query?
Это подход («параметризованный запрос»), при котором текст (структура) SQL-запроса передается на сервер базы данных отдельно от значений параметров. СУБД гарантированно интерпретирует значения именно как данные, не пытаясь выполнить их как часть SQL-синтаксиса.

#### Что такое prepared statement?
Это предварительно подготовленный SQL-запрос («подготовленное выражение»), который СУБД парсит, оптимизирует и кэширует у себя в памяти. Затем этот запрос можно многократно выполнять, подставляя разные наборы параметров с минимальными затратами ресурсов (в Go представлен типом sql.Stmt).

#### Почему placeholder syntax может отличаться в разных СУБД и драйверах?
Потому что каждая система управления базами данных (и реализующие её протокол драйверы) имеет свой диалект SQL. Например, в PostgreSQL используется знак доллара ($1, $2), в MySQL используются знаки вопроса (?), а в SQL Server — параметры вида @p1.
