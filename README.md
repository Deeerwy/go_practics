## Описание проекта
Данный проект демонстрирует использование ORM-библиотеки **GORM** в языке Go для работы с PostgreSQL.  
ORM позволяет описывать модели в виде Go-структур и автоматически создавать таблицы в базе данных.  
GORM значительно упрощает разработку:  
- избавляет от написания шаблонного SQL;  
- обеспечивает безопасность за счёт параметризации запросов;  
- поддерживает миграции и связи между таблицами;  
- ускоряет создание REST API.  

В проекте реализованы:  
- модели `User`, `Note`, `Tag` со связями **1:N** и **M:N**;  
- автоматические миграции через `AutoMigrate`;  
- REST API с ручками `/users`, `/notes`, `/notes/{id}`;  
- выборки с использованием `Preload` для загрузки связанных данных.

## Контрольные вопросы

1. **Что такое ORM и зачем она нужна, если есть database/sql?**  
   ORM (Object–Relational Mapping) — это технология сопоставления объектов программы с таблицами базы данных.  
   **Плюсы:**  
   - Ускоряет разработку за счёт сокращения шаблонного SQL.  
   - Повышает безопасность благодаря параметризации запросов.  
   - Поддерживает миграции и кросс-СУБД.  
   **Минусы:**  
   - Может работать медленнее ручного SQL.  
   - Для сложных аналитических запросов всё равно нужен «сырой» SQL.

2. **Как в GORM описать связи 1:N и M:N? Какие теги на полях вы использовали?**  
   - Связь **1:N**: в модели `User` поле `Notes []Note`.  
   - Связь **M:N**: в модели `Note` поле `Tags []Tag \`gorm:"many2many:note_tags;"\``.  
   - В модели `Tag` аналогично: `Notes []Note \`gorm:"many2many:note_tags;"\``.  

3. **Что делает AutoMigrate? В каких случаях его недостаточно?**  
   `AutoMigrate` автоматически создаёт таблицы и добавляет новые поля, если они появились в структуре.  
   Недостаточно, когда нужно удалить столбцы, изменить типы данных или выполнить сложные миграции — это делается вручную или через внешние инструменты.

4. **Чем Preload отличается от обычного Find/First? Когда его применять?**  
   - `Find`/`First` возвращают только основную сущность.  
   - `Preload` загружает связанные данные (например, автора заметки и её теги) вместе с основной записью.  
   Применяется, когда нужно сразу получить полные данные с отношениями, чтобы избежать дополнительных запросов.
