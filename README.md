# Мониторинг Go-приложения с Prometheus и Grafana. Бурылин Дмитрий ПИМО-01-25

Этот проект демонстрирует базовую настройку мониторинга для backend-приложения на Go с использованием Prometheus для сбора метрик и Grafana для визуализации. Приложение предоставляет HTTP-эндпоинты для работы со студентами, а также публикует метрики в формате Prometheus.

## Цель работы

Освоить организацию мониторинга backend-приложения:
подключение клиента Prometheus к Go-приложению;
публикация метрик через /metrics;
настройка Prometheus для сбора метрик;
подключение Grafana как источника данных;
построение базовых панелей для анализа запросов, ошибок и времени обработки.

## Ответы на контрольные вопросы

1. **Что такое метрики приложения?**  
   Метрики — это числовые показатели, описывающие состояние приложения и его поведение во времени (например, количество запросов, число ошибок, длительность обработки, использование памяти и CPU).

2. **Чем метрики отличаются от логов?**  
   Логи отвечают на вопрос «что именно произошло?» (конкретное событие), а метрики — на вопрос «как система ведёт себя в целом?» (общая динамика). Логи полезны для разбора отдельных инцидентов, метрики — для выявления трендов и аномалий на уровне всей системы.

3. **Какую роль выполняет Prometheus?**  
   Prometheus — система мониторинга, которая собирает и хранит метрики как временные ряды. Он регулярно опрашивает HTTP-эндпоинты приложений (scraping), сохраняет полученные данные и позволяет выполнять запросы на языке PromQL для анализа.

4. **Что такое scraping в Prometheus?**  
   Scraping — это процесс регулярного опроса HTTP-эндпоинта `/metrics` целевого приложения для получения актуальных значений метрик. Prometheus сам инициирует HTTP-запросы к настроенным targets по заданному интервалу.

5. **Зачем приложению маршрут `/metrics`?**  
   Эндпоинт `/metrics` публикует метрики приложения в текстовом формате, понятном Prometheus. Без этого маршрута Prometheus не сможет получить данные для мониторинга.

6. **Что делает `promhttp.Handler()`?**  
   Функция `promhttp.Handler()` из библиотеки `client_golang` возвращает `http.Handler`, который экспонирует метрики из реестра Prometheus (по умолчанию — `DefaultGatherer`) через HTTP. Этот обработчик обычно вешают на путь `/metrics`.

7. **Для чего нужна Grafana?**  
   Grafana — инструмент визуализации данных. Она подключается к Prometheus как к источнику данных и позволяет строить дашборды, графики и панели на основе метрик, делая мониторинг наглядным.

8. **Какие три основные метрики реализованы в этой работе?**  
   - `app_http_requests_total` (Counter) — общее число HTTP-запросов.  
   - `app_http_errors_total` (Counter) — число ошибочных ответов (код ≥400).  
   - `app_http_request_duration_seconds` (Histogram) — длительность обработки запросов в секундах.

9. **Что показывает Histogram?**  
   Histogram (гистограмма) измеряет распределение значений — в данном случае времени обработки запросов. Она подсчитывает, сколько наблюдений попадает в заданные интервалы (buckets), и позволяет вычислять квантили, среднее значение и долю запросов, укладывающихся в определённые временные рамки.

10. **Почему мониторинг важен для сопровождения backend-приложений?**  
    Мониторинг позволяет вовремя увидеть проблемы: рост числа ошибок, замедление ответов, увеличение нагрузки на конкретные маршруты. Без метрик разработчик узнаёт о проблеме только после жалоб пользователей; с метриками можно настроить оповещения и отслеживать поведение системы в динамике, что критично для поддержки надёжности и производительности.
